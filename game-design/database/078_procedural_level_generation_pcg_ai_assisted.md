## 一、核心定位

程序化内容生成（Procedural Content Generation, PCG）是用算法自动生成游戏内容（关卡/地图/物品/任务/叙事）的技术。PCG可以大幅降低内容生产成本，创造无限多样性，同时保证质量可控。2026年，AI大模型的加入让PCG从"规则驱动"进化到"AI驱动+规则约束"的混合模式。

对凌栖项目而言，Arboreus世界引擎的核心就是程序化世界生成，战策已有程序化像素精灵，未来需要程序化地图生成。本条目梳理PCG的核心算法、质量评估方法、AI辅助PCG的最新进展，为Arboreus和战策的程序化内容生成提供参考。

## 二、PCG核心算法

### 2.1 关卡生成算法分类

| 算法 | 说明 | 优点 | 缺点 | 适用 |
|------|------|------|------|------|
| **随机生成** | 纯随机放置元素 | 简单/无限多样 | 质量不可控/常不可玩 | 装饰/背景 |
| **Perlin噪声** | 连续噪声生成地形 | 自然/平滑 | 缺乏结构/无目标 | 地形/高度图 |
| **元胞自动机** | 基于规则的细胞演化 | 有机结构/洞穴 | 参数敏感/难控制 | 洞穴/地牢 |
| **生成语法** | 规则重写生成结构 | 可控/有结构 | 设计复杂/多样性有限 | 建筑/城市 |
| **基于图的生成** | 图结构+布局算法 | 路径可控/可玩 | 实现复杂 | 地牢/关卡 |
| **约束求解** | 定义约束+求解器生成 | 质量保证/可验证 | 计算昂贵 | 谜题/平衡关卡 |
| **进化算法** | 遗传算法+适应度评估 | 可优化目标函数 | 计算慢/需评估函数 | 平衡/优化 |
| **AI大模型** | LLM/VLM生成+约束 | 智能/语义理解 | 幻觉/不可控/成本高 | 叙事/语义内容 |

### 2.2 地牢生成经典算法

**BSP（二叉空间分割）**：
- 将地图递归分割为房间
- 房间之间用走廊连接
- 优点：结构清晰，房间大小可控
- 缺点：可能过于规整

**Drunkard's Walk（醉汉行走）**：
- 随机行走挖掘隧道
- 优点：有机/自然
- 缺点：可能有孤立区域

**元胞自动机洞穴**：
- 随机初始化→迭代规则（4-5规则）
- 优点：自然洞穴形态
- 缺点：需要后处理（连通性检查）

**基于图的地牢**：
- 先生成房间连接图（树/图）
- 再布局到2D空间
- 优点：路径可控，保证可玩
- 缺点：实现复杂

### 2.3 地形生成

**Perlin/Simplex噪声**：
- 多层噪声叠加（fBm）
- 阈值化生成生物群系
- 侵蚀模拟增加真实感
- 无人深空用此方法生成1840亿亿星球

**基于板块的生成**：
- 模拟板块构造
- 生成山脉/海洋/地震带
- 更真实但更复杂

**基于水文的生成**：
- 模拟降水/河流/侵蚀
- 生成自然的水系和地形

## 三、PCG质量评估

### 3.1 为什么需要质量评估

PCG的最大挑战：**生成的内容不一定可玩/有趣/平衡**。
- 随机生成的地牢可能有孤立区域
- 随机地形可能有不可逾越的障碍
- 随机关卡可能太简单或太难
- 需要质量评估来过滤和优化

### 3.2 策略游戏地图的6维适应度

马耳他大学的研究提出了策略游戏地图草图的6维适应度评估：

| 维度 | 说明 | 测量方法 |
|------|------|---------|
| **游戏节奏** | 游戏的快慢节奏 | 资源点距离/路径长度/交战频率 |
| **玩家平衡** | 起始条件的公平性 | 资源量/地形防御性/到中心距离 |
| **区域控制** | 玩家对地图的控制能力 | choke点/高地/视野范围 |
| **探索挑战** | 探索的趣味性和难度 | 迷雾/隐藏区域/路径多样性 |
| **资源分布** | 资源的战略价值 | 资源量/位置/可防守性 |
| **地形多样性** | 地形的丰富度 | 地形类型数量/分布均匀性 |

### 3.3 通用质量指标

| 指标 | 说明 | 好的标准 |
|------|------|---------|
| **可玩率** | 生成的关卡可完成的比例 | >95% |
| **多样性** | 不同关卡之间的差异度 | 高（避免重复） |
| **平衡度** | 双方/多玩家的公平性 | 胜率45-55% |
| **趣味性** | 玩家的主观评价 | >4/5分 |
| **新颖性** | 与已有内容的差异 | 中等（太新颖=不可玩） |
| **一致性** | 与游戏风格的匹配度 | 高 |

### 3.4 评估方法

**自动评估**：
- 基于规则的检查（连通性/可完成性/资源平衡）
- 基于AI的评估（AI玩关卡，测量胜率/时长）
- 基于学习的评估（训练评估模型预测质量）

**人工评估**：
- 设计师审核（抽样检查）
- 玩家测试（A/B测试）
- 社区投票（玩家评分）

**混合评估**：
- 自动过滤（去除不可玩的）
- AI预评分（排序）
- 人工精选（最终选择）

## 四、AI辅助PCG

### 4.1 LLM在PCG中的应用

**LLM生成关卡描述**：
- 用自然语言描述关卡→LLM生成关卡规格
- LLM生成任务/叙事/对话
- LLM评估关卡的趣味性和叙事质量

**VLM生成视觉内容**：
- 文本→图像生成关卡概念图
- 图像→关卡规格（分析截图生成关卡）
- 风格迁移（将关卡转换为不同美术风格）

**AI+规则混合**：
- AI生成创意/语义内容
- 规则保证可玩/平衡/一致性
- AI在规则约束内生成

### 4.2 AI辅助PCG的优势

1. **语义理解**：AI能理解"这个关卡应该有紧张感"之类的语义要求
2. **创意生成**：AI能产生人类设计师想不到的组合
3. **自适应**：AI能根据玩家行为动态调整关卡
4. **自然语言接口**：用自然语言描述想要的关卡

### 4.3 AI辅助PCG的挑战

1. **幻觉**：AI可能生成不存在的机制/物品
2. **不可控**：AI输出不稳定，难以精确控制
3. **成本高**：每次生成都需要API调用
4. **质量不可预测**：同一提示可能产生质量差异很大的结果
5. **版权问题**：AI训练数据的版权争议

### 4.4 最佳实践：AI+规则的混合架构

```
用户输入（自然语言/参数）
    ↓
LLM生成创意方向（主题/风格/关键元素）
    ↓
规则系统生成基础结构（地形/房间/路径）
    ↓
LLM填充语义内容（叙事/任务/对话/装饰描述）
    ↓
自动质量检查（连通性/平衡/可玩）
    ↓
AI评估+人工精选
    ↓
最终关卡
```

## 六、常见陷阱与规避

### 陷阱1：纯随机=垃圾
- **表现**：生成的关卡不可玩/重复/无聊
- **规避**：用规则/约束/评估保证质量，纯随机只用于装饰

### 陷阱2：多样性≠好
- **表现**：追求无限多样性，牺牲可玩性
- **规避**：先保证可玩和有趣，再追求多样性

### 陷阱3：AI万能论
- **表现**：认为LLM可以生成一切
- **规避**：AI+规则混合，AI负责创意，规则负责质量

### 陷阱4：评估缺失
- **表现**：生成了大量内容但质量参差
- **规避**：建立自动+人工的评估流程，质量门控

### 陷阱5：性能问题
- **表现**：生成太慢，影响游戏体验
- **规避**：预生成+缓存，运行时只做轻量调整
